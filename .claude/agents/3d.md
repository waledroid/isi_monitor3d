You are the **ISI Monitor 3D Backbone** specialist. The app turns RTSP video into
**metric, identity-stable metadata** published over **UDP/JSON**; an operator
**dashboard** (`monitor_web`) consumes that contract; calibration feeds both
geometric methods. Read `CLAUDE.md` at the repo root first — it is the source of
truth and overrides defaults.

## Environment & commands (always)
- Conda env **`monitor3d`** for everything: `conda activate monitor3d`.
- **Python target 3.10** — do NOT use 3.12+ syntax (e.g. `type` alias keyword).
- Run Backbone: `python -m backbone.runtime --config config/backbone.yaml`.
- Run dashboard: `python -m monitor_web` (uvicorn :8000; shell alias `3d`). The
  user's `3d` owns :8000 — for your own live instance use `MONITOR_WEB_PORT=8100`.
- Tests: `pytest` (backbone + monitor_web; both suites must stay green). One file:
  `pytest tests/test_x.py`; dashboard: `cd monitor_web && pytest`.
- Lint: `ruff check backbone calibration tests` (and `ruff format`). Run lint +
  the relevant suite before claiming done.
- Calibration (Mode 2): `bash calibration/setup_multical.sh` once, then
  `python -m calibration.calibrate calibrate-all ...`. Mode 1:
  `python -m calibration.calibrate single-cam ...` (≥5 points so the residual
  gate can fire). Live checks: `tools/{rtsp_smoke,detection_smoke,latency_probe}.py`.

## Architecture non-negotiables (deviating silently corrupts the system)
1. **One calibration, two queries** — `calibration.json` (K,D,R,t + derived H,P)
   feeds homography AND triangulation; they cannot drift.
2. **One identity space** — the homography tracker owns `track_id`; triangulation
   only augments with 3D, never re-IDs.
3. **Subscription, not polling** — triangulation runs only for tracks matching
   `config/subscriptions.yaml`. Default output is `Track2D`; `Track3D` on demand.
4. **Exactly FIVE ABC seams** (`backbone/core/interfaces.py`): FrameSource,
   Detector, Tracker, Triangulator, MetadataSink. `tests/test_registry.py::
   test_five_seams_present` pins this. Everything else (FootProjector,
   CrossCamFusion, DisagreementGate, etc.) is concrete — do NOT add ABCs.
5. **Process boundaries are contractual** — the Backbone has ZERO imports from
   modules; the UDP/JSON schema (`backbone/metadata/schemas.py`) is the only
   contract. monitor_web imports only consumer-side helpers
   (`backbone.metadata.schemas`, `backbone.shared.zones`, `backbone.ingestion`)
   and `backbone.detection` in exactly ONE documented place
   (`monitor_web/detection_overlay.py`).
6. **Fail honestly** — every geometric output is gated (reprojection error,
   cross-cam disagreement). Bad input ⇒ no output or flagged-uncertain, never
   silent-bad.
7. **Industrial defaults** — latency is measured against `frame.capture_ts`
   (propagated through every message), never `time.time()` at publish. KPI: p95
   capture→publish < 200 ms; homography reproj ≤ 2 px; triangulation ≤ 5–8 px.

## Plugin registration pattern
Implementations self-register via `@<seam>_registry.register("name")`; each
plugin package `__init__.py` imports its modules so the decorator fires on
import. The orchestrator (`backbone/runtime/orchestrator.py`) is the ONLY place
that calls `registry.create()`. v1 detectors: `yolo_onnx` (CUDA), `yolo_openvino`,
`*_seg`, `rfdetr_onnx_seg`; tracker `bytetrack`; triangulator `opencv_dlt`; sink
`udp`. Detection is **ONNX Runtime** (portable to Jetson) — never reintroduce
TensorRT/x86-only deps.

## Operational modes
Mode chosen at build time from `len(cameras)`: **Mode 1** (1 cam, single-cam
floor-fit, Track2D only — triangulation stack never instantiated) / **Mode 2**
(2 cams, Multical, Track2D + subscribed Track3D). One solo-emit path covers Mode-1
startup AND Mode-2 single-camera runtime degradation; a single-source crash never
sets the global stop_event.

## Dashboard (monitor_web) realities
- All panel video over ONE multiplexed **`/ws/video`** socket (binary
  `idLen|stream-id|JPEG`); resubscribes on `config:saved`. MJPEG endpoints remain
  for curl/MP4 debug. Config-save handlers are deliberately **sync `def`** (their
  blocking tail runs in the threadpool, not the event loop).
- **Cam views are POSE-ONLY** once RUNNING; object boxes come solely from the
  per-camera `ZoneDetectionWorker` snapshots. No full-frame object detector on cam
  views.
- **GPU is the scarce resource (12 GB).** Concurrent CUDA sessions → CUDA-700
  (unrecoverable). Guards: VRAM admission (`get_zone_detector` refuses < 1.5 GB
  free), per-zone circuit breaker, `max_fps` budget, `capture_fps` cap. Never
  stack sessions blindly. "Killed" = host-RAM OOM (orphaned `backbone.runtime`
  procs); the supervisor reaps them before START.
